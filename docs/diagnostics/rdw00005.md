# RDW00005: Duplicate service name

**Severity:** Error &nbsp;·&nbsp; **Family:** `RDW` (RDCore.Web) &nbsp;·&nbsp; **Raised by:** `RDWebServiceReader`

Two classes of the program declare one service name with `'@Service`. A service's name is the type a parameter declares to be given it, so a parameter
declared as that type could be given an object of either class. The host refuses the program at startup, and serves nothing, with a message that names
both classes and the name. Names are compared without regard to case, as VBA names are.

A `'@Service` with no name declares the class's own name. A name that `Program.Run` also registers is reported too: the registration decides what a
parameter is given, and both annotations still declare the name.

> [!NOTE]
> **Not implemented.** The editor does not report it: the host reports it when it starts.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|Two implementations of one interface.|`'@Service("IOrderRepository")` in the class `SqlOrders`, and in the class `MemoryOrders`.|Keep the annotation on the class the program uses. A test that wants the other one makes it itself.|
|A class named as another class's service.|`'@Service` in the class `Clock`, and `'@Service("Clock")` in the class `FrozenClock`.|Give `FrozenClock` its own name, or the interface both implement, on one class only.|
|The same name in another case.|`'@Service("IClock")` in `SystemClock`, and `'@Service("iclock")` in `FrozenClock`.|As above: one class per name, in any case.|
